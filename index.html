The Workflow

From sale circular
to dinner table.

01

Circulars come in

Every Wednesday, Tim pulls sale data from ~10 grocery chains across the Charlottesville region — Kroger via live API (239+ items), and Food Lion, Aldi, Harris Teeter, Giant, Lidl, Walmart, Whole Foods, and Wegmans via Claude Vision PDF extraction. What's on sale this week at your actual stores — not national averages, not estimates.

02

Constraints run first

Before a single item reaches the optimizer, the constraint engine filters the full inventory against the household's dietary profile — allergens, diagnoses, lifestyle rules. Hard exclusions. No exceptions. Every rejection is logged.

03

The plan is built

Five dinners, assembled from what passes constraints and is actually on sale this week. Protein variety enforced. Meal rationale shown. The Sunday Buy-Off lets households approve, swap, or skip each meal before anything gets locked.

04

Found Money, honestly

The shopping list breaks down by store. The Found Money Ledger shows gross savings, trip costs (at $0.22/mile), and net savings. If a store's savings don't cover the drive, we flag it and suggest skipping. Gross numbers are never the headline.

The Core

Safety before savings.
Always. Without exception.

The constraint engine is not a filter. It is a precondition. Before the meal planner sees a single sale item, every item in the week's circular has already passed through the household's dietary profile — allergens, health conditions, lifestyle exclusions, member-specific rules.

This is not a toggle the user can switch off to see better deals. It is not a preference. It is a hard wall that runs every time, on every item, before any optimization happens. A family member's tree nut allergy is not traded for a cheaper dinner. A CKD patient's potassium restrictions are not relaxed to hit a savings target.

Every rejection is logged and shown. If chicken breast was excluded because one member has a poultry sensitivity, that is surfaced. If a particular brand was rejected because it contains a listed allergen, the household sees it. Radical transparency is a founding commitment — there are no black boxes in how plans are built.

This is also the architectural decision that makes the next three Wholly brands straightforward to build. The same constraint engine that handles dietary profiles handles ingredient exclusions in WhollyCare, vet diet restrictions in WhollyPaws, and any filter a household can define. The engine is the platform. WhollyFare is its first application.
